# Плагин cookie-согласия для WordPress (рынок РФ)

Название: **DPTN Cookie Consent** (slug `dptn-cookie-consent`, префикс `dptn_cc_`, см. dptn-plugin-conventions.md).
Дата: 28.10.2026. Статус: проектная спецификация, кода пока нет.

Документ состоит из трёх частей:
1. Черновик решения (роль «агент»).
2. Разбор черновика (роль «критик»).
3. Финальная спецификация с учётом критики. Реализовывать по ней.

> Юридическая оговорка. Ниже инженерная интерпретация 152-ФЗ, а не юридическое заключение. Тексты согласия и политики должен проверить юрист. Суммы штрафов в документе сознательно не приводятся: во вторичных источниках они расходятся, сверять по КоАП ст. 13.11 в редакции 420-ФЗ.

---

## Часть 1. Черновик (агент)

**Цель:** баннер согласия на cookie, своя страница настроек, минимальная нагрузка.

1. Фронтенд берём готовый: библиотека orestbida/cookieconsent v3 с CDN jsDelivr.
2. В `wp_head` PHP читает cookie согласия. Если аналитика разрешена, выводим код Яндекс.Метрики, иначе не выводим.
3. Чтобы ловить скрипты сторонних плагинов, включаем `ob_start()` на весь HTML и регулярками переписываем `<script>` и `<iframe>` известных сервисов.
4. Каждое нажатие кнопки баннера пишем в журнал через `admin-ajax.php`: IP, User-Agent, URL, выбор.
5. Текст баннера: «Продолжая пользоваться сайтом, вы соглашаетесь с использованием cookie», кнопка «Хорошо».
6. Категории: необходимые, функциональные, аналитика, маркетинг.
7. Настройки: по опции на каждое поле (`dptn_cc_text`, `dptn_cc_color`, …).
8. Поддержка WP Consent API обязательна.

## Часть 2. Критика

Проверка по четырём осям: фактическая точность, логика, полнота, соответствие требованиям («только РФ», «самодостаточно», «легко»).

## Часть 3. Финальная спецификация

### 3.1. Принципы

1. **Cache-safe.** HTML одинаков для всех посетителей. Все решения о согласии принимаются в браузере.
2. **Ноль лишней работы на фронте.** Одна autoload-опция, ноль SQL-запросов сверх ядра WP, ноль внешних HTTP-запросов, без jQuery и шрифтов.
3. **Opt-in по умолчанию.** Необязательные сервисы не исполняются до явного согласия.
4. **Самодостаточность.** Нет зависимостей от плагинов, CDN и SaaS. Интеграции включаются сами только при наличии.
5. **Явная модель «сервис → категория».** Блокируем то, что зарегистрировано, а не «угадываем» по всему HTML.

### 3.2. Бюджет производительности (критерии приёмки)

| Метрика | Лимит |
|---|---|
| JS фронта | ≤ 6 КБ gzip, без зависимостей |
| CSS фронта | ≤ 2 КБ gzip, на CSS-переменных |
| HTTP-запросов от плагина | 0 (inline, по умолчанию) или 2 (файлы, опция) |
| SQL-запросов на фронте | 0 сверх autoload-опций |
| PHP-хуков на фронте | только `wp_footer`, `script_loader_tag`, `the_content`, `embed_oembed_html` |
| CLS от баннера | 0 (`position: fixed`) |
| Запись в БД | только при изменении выбора, не чаще N раз в сутки на `consent_id` |
| Код админки | загружается только при `is_admin()` и только на своей странице |

### 3.3. Правовая модель (РФ)

| Требование | Основание | Реализация в плагине |
|---|---|---|
| Согласие конкретное, информированное, сознательное, однозначное | ч. 1 ст. 9 152-ФЗ | Явные кнопки, описание каждой категории и сервиса, без «продолжая пользоваться…». |
| Согласие оформляется отдельно от иных документов | 156-ФЗ, с 01.09.2025 | Отдельная страница «Согласие на обработку cookie и метрических данных», выбор страницы в настройках. |
| Опубликованная политика обработки ПДн | ч. 2 ст. 18.1 | Ссылка на политику в баннере (выбор страницы). |
| Право отзыва согласия | ч. 2 ст. 9 | Ссылка `#dptn-cc-settings`, шорткод `[dptn_cc_settings]`, плавающая кнопка. |
| Обязанность доказать получение согласия | ч. 3 ст. 9 | Журнал согласий с версией текста. |
| Первичный сбор через базы в РФ | ч. 5 ст. 18 (ред. с 01.07.2025) | Журнал хранится в БД сайта. В админке подсказка: хостинг должен быть в РФ. Ассеты только локальные. |
| Трансграничная передача | ст. 12 | Пресеты зарубежных сервисов (GA, YouTube) помечены предупреждением о необходимости уведомить РКН. |

**Вне зоны плагина (чек-лист в админке, вкладка «Справка»):** уведомление РКН об обработке ПДн (ст. 22), согласия в формах обратной связи (отдельный чекбокс, не проставленный по умолчанию), тексты политики и согласия от юриста.

**Режимы работы:**
- **Строгий** (по умолчанию). Необязательные сервисы ждут согласия.
- **Уведомление.** Сервисы грузятся сразу, баннер только информирует и даёт отказаться. В админке красное предупреждение: режим не соответствует требованию однозначного согласия, ответственность на владельце сайта.

**Bootstrap:** на `plugins_loaded` грузим `Settings`. Если `is_admin()`, то `Admin`. На фронте `Frontend` и `Blocker`. На `rest_api_init` только `Rest`. Никаких классов «на всякий случай».

### 3.5. Хранение согласия в браузере

Cookie `dptn_cc` (first-party, `path=/`, `SameSite=Lax`, `Secure` на HTTPS, без `HttpOnly`, потому что его читает JS).

Значение компактное: `v{версия}.{категории битами}.{unix-время}.{consent_id}`, например `v3.5.1761638400.9f1c…`.

- **Версия** растёт при изменении текста согласия или состава сервисов. Если она не совпадает, баннер показывается снова.
- **Срок жизни** по умолчанию 12 месяцев, настраивается. Тот же срок указывается в тексте согласия.
- `localStorage` не используем: cookie читается и в PHP для некешируемых сценариев.

### 3.6. Фронтенд

**Порядок работы JS (`defer`, в футере):**
1. Прочитать cookie `dptn_cc`. Если согласие есть и версия актуальна, активировать разрешённые сервисы и выйти. Баннер не показывается и даже не строится в DOM.
2. Иначе построить баннер из inline-конфига (`<script type="application/json" id="dptn-cc-config">`) и показать его.
3. На выбор: записать cookie, активировать сервисы, отправить `navigator.sendBeacon` на REST (если журнал включён), выбросить событие.

**Активация заблокированных скриптов:** элементы `script[type="text/plain"][data-dptn-cc]` клонируются в новый `<script>` с исходными атрибутами (`src`, `async`, inline-код). Это паттерн orestbida/Klaro, на нём держится вся схема.

**Iframe:** `src` переносится в `data-dptn-cc-src`, на месте фрейма плейсхолдер «Контент VK Видео / Яндекс.Карт использует cookie. [Включить] [Настроить]». Клик «Включить» разрешает только этот сервис.

**Отзыв:** при снятии категории удаляем cookie сервиса по маскам (`_ym_*`, `_ga*`, `tmr_*` …) для текущего домена и домена с точкой, затем `location.reload()`. Уже исполненный скрипт иначе не выгрузить.

**UI баннера:**
- Кнопки «Принять все», «Только необходимые», «Настроить» одинаковой визуальной значимости.
- Панель настроек: переключатели категорий, раскрывающийся список сервисов с описанием и списком cookie.
- `role="dialog"`, `aria-labelledby`, перевод фокуса на баннер, `Esc` закрывает панель настроек (но не баннер), видимый фокус, контраст ≥ 4.5:1.
- `position: fixed`, позиции: низ, низ-слева, низ-справа, по центру с затемнением.
- Цвета, радиус и шрифт через CSS-переменные `--dptn-cc-*`, тема может их переопределить.

**Публичный JS API:**
```js
window.dptnCC.has('analytics')        // boolean
window.dptnCC.show()                  // открыть настройки
window.dptnCC.onChange(cb)            // подписка
document.addEventListener('dptn-cc:change', e => e.detail.categories)
```

### 3.7. Блокировка на стороне PHP (без буферизации)

1. **Сервисы плагина.** Админ включает пресет (Метрика: вводит номер счётчика и флаги вебвизора) или вставляет произвольный код. Плагин сам выводит его как `type="text/plain" data-dptn-cc="analytics"`.
2. **Скрипты тем и плагинов.** Таблица «handle → категория» в настройках. Фильтр `script_loader_tag` меняет `type` у этих handle. Работает только для `wp_enqueue_script`, это ограничение документировано.
3. **Iframe в контенте.** Фильтры `the_content` и `embed_oembed_html` с одной регуляркой только по `<iframe` и только по доменам из включённых пресетов. Есть быстрый выход: `strpos($html, '<iframe') === false`.
4. **Ручная разметка.** Разработчик сам пишет `<script type="text/plain" data-dptn-cc="marketing">`.

Для некешируемых контекстов (личный кабинет, AJAX) есть `dptn_cc_has_consent( 'analytics' )`. В документации предупреждение: на кешируемых страницах не использовать.

### 3.9. Журнал согласий

Включается в настройках (по умолчанию включён в строгом режиме).

**Таблица `{prefix}dptn_cc_log`:**

| Поле | Тип | Комментарий |
|---|---|---|
| `id` | BIGINT UNSIGNED AI | |
| `consent_id` | CHAR(36) | UUID из cookie, индекс |
| `created_at` | DATETIME | время **сервера** |
| `version` | SMALLINT | версия текста согласия |
| `categories` | TINYINT | битовая маска |
| `action` | TINYINT | accept_all / necessary / custom / withdraw |
| `ip` | VARBINARY(16) NULL | опция, по умолчанию выкл.; усечённый или хеш с солью |

**REST** `POST /wp-json/dptn-cc/v1/consent`:
- Без nonce: на кешированной странице nonce протухает. Вместо него строгая валидация (UUID, диапазоны чисел, размер тела ≤ 256 байт).
- Дедупликация: одна запись на `consent_id + version + categories`.
- Лимит: не больше 10 записей на `consent_id` в сутки, глобальный суточный потолок (опция), сверх него запросы молча отбрасываются.
- Текст версии согласия хранится в опции `dptn_cc_versions` (autoload = false): номер, дата, хеш текста. Так видно, с каким текстом согласился пользователь.

**Очистка:** WP-Cron раз в сутки удаляет записи старше срока хранения (по умолчанию 3 года, настраивается). Срок согласовать с юристом.

**Админка:** поиск по `consent_id` (посетитель может назвать его из панели настроек), фильтр по датам, экспорт CSV, счётчики «принято / только необходимые / отозвано».

### 3.10. Страница настроек

Меню: **Настройки → Cookie-согласие**. Нативный Settings API, без React и сборки. Ассеты: `wp-color-picker` и свой `admin.js` около 3 КБ, только на этом экране.

| Вкладка | Содержимое |
|---|---|
| Основное | Режим (строгий / уведомление), заголовок и текст баннера, подписи кнопок, страница согласия, страница политики, срок жизни cookie, кнопка «Повысить версию согласия». |
| Сервисы | Включение пресетов, их параметры (номер счётчика и т. п.), произвольный код, таблица «handle → категория». |
| Категории | Названия и описания, включение четвёртой категории. |
| Внешний вид | Позиция, цвета, радиус, плавающая кнопка отзыва, живой предпросмотр. |
| Журнал | Включение, хранение IP, срок хранения, просмотр, экспорт CSV. |
| Справка | Чек-лист по 152-ФЗ, шорткоды, JS API, импорт/экспорт настроек в JSON. |

Все поля проходят `sanitize_callback`, произвольный код сервисов разрешён только пользователям с `unfiltered_html`. Права доступа к странице: `manage_options`.

### 3.11. Интеграции (все опциональные)

- **WP Consent API:** если функции есть, транслируем категории (`statistics`, `marketing`).
- **Google Tag Manager:** контейнер целиком как сервис категории «аналитика» плюс событие `dptn_cc_consent` в `dataLayer`.
- **Кеш-плагины:** действий не требуется (HTML одинаков). После смены настроек вызываем `wp_cache_flush()` и документируем, что страничный кеш нужно сбросить.

### 3.12. Чего сознательно нет

- Сканера cookie (тяжёлый, нужен headless-браузер, у Complianz/CookieYes это SaaS).
- Геотаргетинга, IAB TCF, Google Consent Mode, мультиязычности: не нужны для РФ-only.
- Глобальной буферизации HTML (см. К3).
- Генератора юридических текстов: только шаблон-подсказка с пометкой «проверить у юриста».

### 3.13. План работ

1. Ядро: `Settings`, `Frontend`, `consent.js` с баннером и активацией скриптов, пресет Метрики. Проверить бюджет §3.2.
2. Страница настроек: вкладки «Основное», «Сервисы», «Внешний вид».
3. Блокировка iframe и `script_loader_tag`, остальные пресеты.
4. Журнал и REST, cron-очистка, экспорт.
5. Отзыв согласия, плавающая кнопка, доступность.
6. Тесты: с WP Rocket / LiteSpeed Cache, без JS, на мобильных, проверка, что до согласия в Network нет запросов к `mc.yandex.ru`.
