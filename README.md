# DPTN Cookie Consent

Разработчик: DPTN — https://dptn.pro

Лёгкий баннер согласия на cookie для сайтов РФ. Совместим со страничным кешем: HTML одинаков для всех, решение о запуске сервисов принимается в браузере.

Статус: этапы 1–5 из спецификации (ядро, баннер, Яндекс.Метрика, страница настроек, блокировка скриптов по handle и iframe, журнал согласий, отзыв и доступность).

Журнал согласий: таблица `{prefix}dptn_cc_log`, запись через `POST /wp-json/dptn-cc/v1/consent` (sendBeacon),
дедупликация и суточные лимиты, ежедневная очистка по сроку хранения (WP-Cron `dptn_cc_cleanup`),
просмотр, поиск по ID согласия и выгрузка CSV на вкладке «Журнал». IP по умолчанию не сохраняется.
Реестр версий согласия (`dptn_cc_versions`): дата, страница и SHA-256 текста согласия, список сервисов.

Отзыв согласия: ссылка `#dptn-cc-settings`, шорткод `[dptn_cc_settings]` или плавающая кнопка (опция «Внешнего вида»).
Доступность: баннер первым в DOM, объявление выбора через `role="status"`, фокус не теряется, цели касания 44px,
режим высокой контрастности, `prefers-reduced-motion`, проверка контраста цветов в админке.

Скрипты темы и плагинов блокируются по handle (Настройки → Cookie-согласие → Сервисы, есть поиск по главной странице).
Если от заблокированного скрипта зависят незаблокированные, после согласия страница перезагружается.
Iframe YouTube, RUTUBE, VK Видео, Яндекс.Карт и Google Карт в записях заменяются заглушкой до согласия на «Функциональные».

Проверено со страничным кешем WP Super Cache 3.1.4 и WP Rocket 3.23.5.1: гости получают один и тот же файл кеша
при любом состоянии согласия, запуск сервисов, заглушки и отзыв работают на закешированных страницах.
С WP Rocket проверены также отложенный запуск JS (Delay JS), defer, минификация JS и ленивая загрузка iframe/YouTube.
Скрипт баннера и встроенные скрипты помечены атрибутами `data-no-optimize`, `data-no-defer`, `data-noptimize`,
`data-cfasync="false"`; для WP Rocket исключения регистрируются его фильтрами (`includes/class-compat.php`).

## Установка

Скачать `dptn-cookie-consent.zip` со страницы [последнего релиза](https://github.com/dptnpro/dptn-cookie-consent/releases/latest)
и загрузить в «Плагины → Добавить новый → Загрузить плагин». Архив исходного кода (Source code) не подходит:
в нём папка с другим именем.

Новые версии появляются в «Консоль → Обновления» и ставятся как обычные, работают и автообновления.
Плагин раз в 6 часов скачивает `info.json` последнего релиза (`includes/class-updater.php`), «Проверить снова» сбрасывает кеш.
Версии до 0.4.0 обновлений не получают: их нужно один раз заменить вручную.

## Настройка

**Настройки → Cookie-согласие**: режим, страницы согласия и политики, тексты, сервисы, внешний вид.
Старый код Метрики из темы нужно удалить, иначе он будет работать без согласия.

Из кода темы настройки можно переопределить фильтром — значения из фильтра важнее сохранённых в админке:

```php
add_filter( 'dptn_cc_settings', function ( $s ) {
	$s['style']['accent'] = '#e30613';
	return $s;
} );
```

## Свои сервисы

- Через фильтр `dptn_cc_services` (см. комментарий в `includes/class-services.php`).
- Вручную в шаблоне: `<script type="text/plain" data-dptn-cc="marketing">…</script>`. Для `type="module"` добавьте `data-type="module"`.

## API

```js
dptnCC.has('analytics');            // разрешена ли категория
dptnCC.show();                      // открыть настройки
dptnCC.onChange(cats => {});        // подписка на изменение выбора
document.addEventListener('dptn-cc:change', e => e.detail.categories);
```

Ссылка «Настройки cookie» в любом месте сайта: `<a href="#dptn-cc-settings">Настройки cookie</a>`.

PHP (только на некешируемых страницах): `dptn_cc_has_consent( 'analytics' )`, `dptn_cc_get_consent()`.

## Сборка

```bash
npm install && npm run build && npm run size
```

Без сборки плагин берёт исходники из `assets/src/`.

## Выпуск версии

1. Поднять версию в заголовке `Version:` и в `DPTN_CC_VERSION` (`dptn-cookie-consent.php`), при необходимости `Tested up to:`.
2. Добавить раздел `## X.Y.Z` в `CHANGELOG.md`.
3. `npm run build`, закоммитить вместе с `assets/*.min.*`.
4. `git tag vX.Y.Z && git push origin main vX.Y.Z`.

GitHub Action (`.github/workflows/release.yml`) сверит версии, пересоберёт ассеты, соберёт zip через `git archive`
(без файлов из `export-ignore` в `.gitattributes`) и опубликует релиз с `dptn-cookie-consent.zip` и `info.json`.
Сайты увидят обновление при следующей проверке.
